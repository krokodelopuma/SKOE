Выполнение
Отчет по разработанной системе трекинга плоских объектов

1. Теоретическая база

Трекинг плоского объекта - оценки положения и ориентации плоской поверхности (требуется найти гомографию)

Гомография корректно описывает проективное преобразование именно плоской поверхности, поэтому любой четырехугольник на изображении можно восстановить, применив H к углам шаблона.

SIFT детектор и дескриптор ключевых точек, инвариантный к масштабу, повороту и частично к изменению освещения. Применяется для поиска соответствий между шаблоном и текущим кадром.

FLANN-матчер - быстрый приближенный поиск ближайших соседей в пространстве дескрипторов. Для SIFT используется KD-дерево.

Lowe ratio test - фильтрация соответствий: пара (m, n) принимается, если m.distance < 0.75 · n.distance, что отсекает неоднозначные совпадения.

RANSAC + findHomography - робастная оценка гомографии при наличии выбросов среди соответствий.

Пирамида шаблона - шаблон детектируется на нескольких масштабах (1.0, 0.75, 0.5, 0.35), что повышает устойчивость при сильном удалении/приближении объекта.

Оптический поток Лукаса–Канады (Pyramidal LK) - отслеживание персистентного набора точек объекта между соседними кадрами (calcOpticalFlowPyrLK) с пирамидой и критерием остановки итераций.

Геометрическая стабилизация квада - восстановление сломанной вершины четырехугольника по трем остальным через свойство параллелограмма:


Это работает, поскольку при аффинном (и приближенно при слабо-проективном) преобразовании диагонали параллелограмма делятся пополам, а зеркальная вершина восстанавливается линейно.

Сглаживание (EMA) - экспоненциальное сглаживание координат углов для устранения дрожания рамки.

2. Описание разработанной системы (алгоритмы, принципы работы, архитектура)

Система реализована в виде класса PlaneTracker с публичным методом track(frame) и вспомогательными модулями:

set_target(image) - инициализация: построение пирамиды шаблона, выбор до 200 ключевых точек, расчет радиусов точек от центра.
_match_scale / _match_all_scales - матчинг шаблона с кадром на всех масштабах пирамиды, выбор лучшего по числу инлайеров.
_track_optical_flow - LK-трекинг персистентных точек obj_pts_f.
_reinit_points_from_match - переинициализация набора точек по результатам матчинга (с переиспользованием слотов).
_restore_points_from_corners - восстановление положений точек по найденной рамке через гомографию.
_stabilize_quad - геометрическая коррекция вершин, центрирование по облаку точек.
_check_points_in_quad - проверка, что ≥60 % живых точек попадает внутрь рамки.
_smooth - EMA-сглаживание углов.
draw_debug - визуализация: рамка, векторы потока, точки, миниатюра шаблона, статус.

2.2. Персистентный набор точек объекта

Ключевая идея системы - вместо покадрового детектирования поддерживается постоянный набор из ≤200 точек (obj_pts_t, obj_pts_f, obj_valid, has_template):

- obj_pts_t - координаты точки в системе шаблона (не меняются);
- obj_pts_f - ее текущее положение на кадре;
- obj_valid - жива ли точка (прошла ли LK-трекинг);
- has_template - занят ли слот (для переиспользования).

Это позволяет строить гомографию H между obj_pts_t и obj_pts_f по RANSAC даже без повторного матчинга, что дает покадровую оценку позы и высокую частоту обновления.

2.3. Основной цикл track()

Алгоритм работает как каскад с приоритетами:

Шаг 0. Подготовка. Вычисляется площадь предыдущей рамки, определяется флаг is_far_away (площадь < 5 % начальной), сбрасывается force_no_flow_next.

Шаг 1. Оптический поток (основной канал).
- LK-трекинг всех живых точек; мертвые помечаются obj_valid=False.
- По внешним (наиболее удаленным от центра) точкам через findHomography (RANSAC) вычисляется Hf.
- Кандидат-квад проверяется: валидность (_is_valid_quad), стабилизация (_stabilize_quad), проверка _check_points_in_quad (≥60 % точек внутри).
- Дополнительно - контроль скачка площади: отношение a_new/a_last должно быть в диапазоне [0.8, 1.25], иначе flow сбрасывается (force_no_flow_next = True) и на следующем кадре flow отключается.
- При сильной потере точек (<30 % от исходных) - восстановление по найденной рамке.

Шаг 2. Матчинг по пирамиде (коррекция).
- Поиск лучшего совпадения по всем масштабам шаблона.
- Если flow упал или точек <15 - принудительная переинициализация набора точек по инлайерам матчинга, сброс сглаживания и блокировки flow.
- Если flow валиден - сравнение площадей; при расхождении >25 % переинициализация по матчу.
- Если рамки нет вовсе - принимается рамка по матчу и точки восстанавливаются.

Шаг 3. Восстановление рамки по облаку точек. Если после шагов 1–2 рамки нет, но живых точек ≥6 - строится Hf по obj_pts_t->obj_pts_f, кандидат проходит те же проверки (валидность + _check_points_in_quad).

Шаг 4. Fallback: 4 угла с прошлого кадра. Простой LK-трекинг по 4 углам prev_corners/last_confirmed_corners. Помечается как неподтвержденный результат.

Шаг 5. Финал. Повторная стабилизация, EMA-сглаживание только для подтвержденных рамок, сохранение prev_corners, last_confirmed_corners, prev_gray.

Возврат: (corners, confirmed) или (None, False).

2.4. Защитные механизмы

force_no_flow_next - блокирует flow на один кадр после плохого результата, чтобы не накапливать ошибку.
_check_points_in_quad(threshold=0.6) - отбрасывает рамку, уехавшую с объекта (точки снаружи).
Контроль скачка площади - не даёт рамке резко сжиматься/растягиваться от одного кадра.
is_far_away (площадь <5 %) - отключает проверки площади и включает центрирование рамки по облаку точек при сильном удалении.
_stabilize_quad - восстанавливает сломанные вершины, проверяет близость к предыдущим углам (near_tol=12).
EMA-сглаживание (α=0.6–0.7) - устраняет дрожание рамки.
Переинициализация точек по матчу - восстанавливает набор точек после потери трека.

2.5. Визуализация (draw_debug)

Отображается: рамка (зеленая - подтверждена, желтая - только flow), 4 угла (красные), векторы потока (желтые линии), живые точки (кружки), миниатюра шаблона с нанесенными ключевыми точками в правом верхнем углу, статусная строка match/flow [FLOW/NO-FLOW] points=N.

2.6. Пакетная обработка

main() ищет видео по маске mona-lis*.avi, для каждого запускает process_video(), пишет результат в *_tracked.avi (XVID), собирает статистику (кадров всего / с рамкой / подтвержденных) и выводит сводную таблицу.


3. Результаты работы и тестирования системы

Для каждого видео выводятся:

- Кадров - общее число;
- Рамка - доля кадров, где рамка найдена (любым способом);
- Подтверждено - доля кадров с confirmed=True (flow или матч, а не fallback).

Дополнительно по статусной строке можно оценить долю кадров в режимах FLOW / NO-FLOW и число живых точек.

Сценарии
1. Нормальный трекинг - flow держит рамку, периодически подтверждается матчингом; количество точек поддерживается восстановлением при просадке <30 %.
2. Быстрое движение / смаз - LK теряет точки, n_after_flow падает, срабатывает переинициализация по матчу; рамка не съезжает благодаря _check_points_in_quad.
3. Частичное перекрытие - часть точек помечается obj_valid=False; при ≥60 % внутри рамки трек продолжается, при меньшем - рамка перестраивается по матчу.
4. Сильное удаление (площадь <5 %) - включается is_far_away: отключаются проверки площади, рамка центрируется по облаку точек, чтобы компенсировать сжатие к центру.
5. Полная потеря - fallback по 4 углам; при неудаче возвращается (None, False), lost_counter растет.

3.3. Критерии корректности, заложенные в систему

- Квад выпуклый, площадь в допустимых пределах (кроме режима is_far_away).
- Отношение max/min стороны ≤15, min сторона ≥3 px.
- >60 % живых точек внутри рамки.
- Площадь не скачет более чем на ±25 % за кадр (вне режима удаления).
- Вершины близки к предыдущим (≤12 px) - иначе восстанавливаются геометрически.


4. Выводы по работе

1. Разработана гибридная система трекинга плоского объекта, объединяющая три независимых канала оценки позы: оптический поток по персистентному набору точек, матчинг SIFT-признаков по пирамиде масштабов и геометрическое восстановление рамки по облаку точек. Каналы работают по приоритетам с взаимной коррекцией.

2. Ключевое архитектурное решение - персистентный набор до 200 точек объекта с флагами obj_valid/has_template. Это позволяет строить гомографию покадрово по RANSAC без повторного детектирования, переиспользовать слоты при переинициализации и естественно интегрировать матчинг как ремонтный механизм.

3. Реализован комплекс защитных механизмов: проверка попадания точек в рамку (>60 %), контроль скачка площади (+-25 %), блокировка flow после сбоя, геометрическая стабилизация вершин, режим сильного удаления, EMA-сглаживание. Именно они обеспечивают устойчивость к перекрытиям, смазу и резким изменениям масштаба.
